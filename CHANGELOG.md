# Changelog

All notable changes to this project will be documented here.

## [Unreleased]

### Fixed
- `find_smallest_gte()` — removed stray debug `print(v, value)` in the linear scan path
- `dec_to_hex_str()` — `NameError` when `byte_size=0` (hex_str was conditionally assigned then always read)
- `send_webhook()` — status code check had `201` duplicated; corrected to `200 or 201 or 202`
- `get_rows()` / `insert()` / `create_table()` etc. — SQL identifier injection: table and column names now validated and double-quoted via `_sql_id()`
- `win_automation_utils` — `ImportError` on non-Windows platforms
- `EquationSolver` — `eval()` exposed Python builtins; restricted to `{'__builtins__': {}}` so only sympy symbols are in scope (windll imported unconditionally); now raises a clear `ImportError` on non-Windows at import time

### Added
- `tools/launcher.py` — Tools launcher: finds every `utils/tools` subfolder with a `tool.toml` manifest (`name`, `entry = "package.module:function"`, optional `description`, `order`) and shows one button per tool; a click imports the tool and embeds the widget its entry function returns. Manifests are read without importing, so a tool with missing packages fails only on its own button; an unreadable manifest gives a disabled button with the reason. `discover_tools()` returns the list. Manifests added for Env Path Editor, Portable Apps Manager and Task Scheduler. Embedded in `work_dir/tools_launcher.py` as "lib-utils Tools"
- `tools/task_scheduler` — Task Scheduler: ipywidgets UI and API (Windows Task Scheduler COM API via pywin32) to add, list, enable / disable, run, stop and remove scheduled tasks, e.g. to start a monitor at boot or resume a test script after a restart. Basic settings: one exec action, triggers at startup / at log on (with delay) / daily / once, run whether logged on or not (password, or S4U) or only when logged on, highest privileges, priority (default normal, 4), time limit (default none), run on battery (default allowed), multiple instances (default ignore new); `export_xml()` / Show XML for the full definition. `add_python_script()` runs a script with the current interpreter in the script's folder. Passwords are asked for in the Windows password dialog (or passed from a script) and go to Windows only, never stored. Jupyter / Python stays non-elevated: changes that need administrator rights (at-startup triggers, S4U, highest privileges, changing tasks registered with administrator rights) run in a short-lived elevated helper after a UAC prompt, one prompt per batch, with a plain description of the change in the prompt's details and a notice just before it (`elevate='auto'`, the default; `False` for access denied instead). Actions take one task or a list; `delete_folder()` removes an empty task folder; `register_task(source=...)` marks a task as a tool's own (`TaskInfo.source`). COM errors become `TaskSchedulerError` with the reason
- `tools/portable_apps_manager` — Portable Apps Manager: ipywidgets UI to add (deploy + track), update, untrack and delete portable Windows apps from GitHub releases or fixed download URLs (URL apps detect updates from the redirect target's version, ETag or Last-Modified - chosen per app from what the server sends - and take the shown version from a file in the archive, e.g. adb's `source.properties`, the archive's top folder name, e.g. `node-v26.13.0-win-x64`, or the downloaded file name - chosen per app via `version_from`, default `auto`). A git-tracked `apps_catalog.ini` records how each app is best tracked (with a note); the Add form fills from it and "Save to catalog" writes tracked apps back, so recipes are shared by committing the file. A PATH column puts each app's `bin` folder on the User PATH (via `tools/env_path_editor`; appended, `%USERPROFILE%`-based, read live from the registry, backed up before each write); Untrack asks whether to remove the entry, Untrack & delete removes it. Prerequisite: `truststore` (added to the `[requests]` extra), so HTTPS verification uses the Windows certificate store and works behind corporate TLS inspection. Apps and installed versions live in `<root>/portable_apps.ini` (root defaults to `~\Downloads\Programs`, changeable per session). Assets are picked by a glob/regex that must match exactly one asset; updates compare the archive listing (size + CRC32, zip/7z/.7z.exe/tar) against the folder without extracting, write only new/changed files, never touch `preserve` globs, refuse to start while a file to be replaced is in use, and ask per file which stale files to remove. Each install writes an install manifest (`<root>/portable_apps.manifests/<name>.json`: every file written, with size + CRC32), so the next update leaves files the tool never wrote (app settings, user data) alone without a `preserve` glob, and keeps shipped files that were edited since the install unless the user picks them for overwrite. The ini is written one app at a time (re-read, that app's section replaced or removed, written back), and every action re-reads it first when it changed on disk, so hand edits and a second copy of the tool are not overwritten
- `tools/env_path_editor` — Env Path Editor: ipywidgets UI and API to view, check and edit the Windows User and System PATH (raw registry values, `%VAR%` entries kept unexpanded, value type kept). Flags empty entries, unresolved variables, relative paths, missing folders, files, duplicates (compared as expanded absolute paths, case- and trailing-backslash-insensitive) and User entries already in System. No sorting: Move up / down, Add / Add at top / Replace selected, Remove selected, Select flagged, Remove duplicates & empty. Save refuses if either PATH changed outside the tool since load, optionally backs up both raw values to `%TEMP%\env_path_editor_backups` (`restore_backup()` writes one back exactly), then broadcasts `WM_SETTINGCHANGE`. System is read-only unless running as administrator. API for other tools: `update_user_path(add, remove, prepend, backup_first)`, `add_user_path`, `remove_user_path`, `in_path`
- `pyproject.toml` — modern packaging metadata with `extras_require` groups (`requests`, `git`, `crypto`, `pdf`, `slack`, `selenium`, `math`, `win`, `all`)
- `README.md` — package layout, install instructions, usage examples

### Changed
- `requires-python` raised to `>=3.11` (`tools/launcher.py` reads `tool.toml` with the standard-library `tomllib`)
- `requirements.txt` — rewritten as a flat `>=` mirror of the `pyproject.toml` dependencies (same floors), replacing the stale pip-freeze pins (`cryptography==45.0.7` contradicted pyproject's `>=48.0.1`); added previously missing sections (`ipython` core, `[sql]`, `[cv]`, `[clipboard]`, `[pillow]`, `[widgets]`); dropped transitive `pywin32-ctypes`. `pip-audit` re-run 2026-07-18 on the full resolved set (73 packages incl. transitives): no known vulnerabilities

### Removed
- `setup.py` — the shim (all metadata already lived in `pyproject.toml`) is no longer needed; PEP 660 editable installs work from `pyproject.toml` alone with `setuptools>=68`
