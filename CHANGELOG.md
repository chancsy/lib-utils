# Changelog

All notable changes to this project will be documented here.

## [Unreleased]

### Fixed
- `get_date_range()` — month / year steps kept the start day and raised `ValueError` when a later month or year didn't have it (`2026-01-31` by month: "day 31 must be in range 1..28"; Feb 29 by year). Now each date is computed from the start date and clamped to the month's last day (stdlib `calendar.monthrange`): Jan 31 -> Feb 28 -> Mar 31 -> Apr 30; Feb 29 by year -> Feb 28, and Feb 29 again in leap years. Start days 1-28 give the same dates as before
- `send_webhook()` / `post_to_teams()` — posted with TLS verification off (`verify=False`, for the office proxy). Now verified against the Windows certificate store via `truststore` (the `[requests]` extra; scoped to the request's session, as in `tools/portable_apps_manager`), which also trusts the proxy's corporate root CA. New `verify=True` parameter: `verify=False` restores the old behaviour. **Not yet tested on the office network** (see the TODO comment in `send_webhook()`)
- `os_version_win()` — stopped at 24H2 (build 26100), so 25H2 PCs reported "Unknown Windows version". Adds 25H2 (26200), 26H1 (28000, new Arm PCs only) and 26H2 (26300); reads the build from `sys.getwindowsversion()` instead of parsing `platform.platform()`; a build not in the table now says `Unknown Windows version (build N)`
- `get_date_range()` — an `increment` other than `'day'` / `'month'` / `'year'` looped forever (the date never advanced); now raises `ValueError` before starting
- `wait_TimePassed()` — ignored `tick_s` and always polled every 10 ms; now checks every `tick_s` seconds, never sleeping past the deadline (a large `tick_s` doesn't overshoot `duration`). `sleep()` / `sleep_progress()` keep the 10 ms default
- `get_serial_number()` — returned the hostname (`platform.node()`, a placeholder since the first commit), so the test banner's `SN=` was the PC name. Now the hardware serial: Windows `Win32_BIOS.SerialNumber` (CIM, as `wmic` is gone), macOS `IOPlatformSerialNumber`, Linux DMI `product_serial` (usually root-only), then the device tree / `/proc/cpuinfo` serial (Raspberry Pi and other ARM boards). `None` if unavailable or a firmware placeholder ("To Be Filled By O.E.M." etc.)
- `SQLite.create_table()` — its docstring came after a `_sql_id()` call, so Python didn't treat it as a docstring (no `help()` text, no API.md summary); the call now follows the docstring, same behaviour
- `find_smallest_gte()` — removed stray debug `print(v, value)` in the linear scan path
- `dec_to_hex_str()` — `NameError` when `byte_size=0` (hex_str was conditionally assigned then always read)
- `send_webhook()` — status code check had `201` duplicated; corrected to `200 or 201 or 202`
- `get_rows()` / `insert()` / `create_table()` etc. — SQL identifier injection: table and column names now validated and double-quoted via `_sql_id()`
- `win_automation_utils` — `ImportError` on non-Windows platforms
- `EquationSolver` — `eval()` exposed Python builtins; restricted to `{'__builtins__': {}}` so only sympy symbols are in scope (windll imported unconditionally); now raises a clear `ImportError` on non-Windows at import time

### Added
- `AdbUtils` wireless (Wi-Fi) adb: `connect(address)` returns the serial once the device is usable (waits out offline / unauthorized), `disconnect()`, `pair(address, code)` for Android 11+ Wireless debugging, `mdns_services()` lists devices advertised on the LAN (Wireless debugging's random port changes on every toggle - this finds it again), `switch_to_wifi(port=5555)` moves a USB device to Wi-Fi via `adb tcpip` (any Android version, until reboot), `get_wifi_ip()`, `is_wireless(serial)`. `get_hardware_serial()` (`ro.serialno`) identifies a device the same way over USB and Wi-Fi, where the adb serial becomes `host:port`. Demo entries k-o
- `standalone/scrcpy_utils` — scrcpy (Android screen mirroring) helpers, moved from life_makeover_tools `common/lm_adb.py`: `launch_scrcpy()` attaches to the window with the given title or launches scrcpy with it (`--window-title`, `--always-on-top`, `--no-audio`, `--video-bit-rate`, `-s`) and returns a `ScrcpyCapture` (`take_screenshot()` = BGR frame of the window's client area, drop-in for `AdbUtils.take_screenshot()`; `stop()` closes scrcpy only if we launched it). `find_scrcpy(exe)` = the given path (file or folder) else `scrcpy` on PATH - a stale given path warns and falls back to PATH, so a configured path is optional (portable_apps_manager puts scrcpy on PATH). `resolve_adb(adb_path)` = explicit path > the adb bundled with scrcpy > `adb` on PATH, so the tool and scrcpy share one adb client; `launch_scrcpy(adb_path=)` passes it to scrcpy as `ADB`. Launch now fails fast with `RuntimeError` if scrcpy exits (device unauthorized) and with `FileNotFoundError` if scrcpy isn't found. New `[scrcpy]` extra (`[win]` + `[cv]` + `mss`)
- `.githooks/pre-commit` — when a commit touches `utils/`, regenerates API.md and stops the commit if it changed or isn't staged. Enable per clone with `git config core.hooksPath .githooks`; `.gitattributes` keeps `.githooks/*` LF so the shell script runs after a Windows checkout
- `API.md` + `scripts/gen_api_index.py` — generated signatures-only index of the public API (about 11% of the source size): a contents table with each module's third-party imports, top-level names and line range in API.md, then one line per class / function / method with its source line, parameters (types omitted, long lists cut with `…`) and a one-line summary (docstring's first paragraph, else the comment block above the `def`). Private `_x.py` modules in a package are included only for the names the package's `__init__.py` re-exports; tool UI classes (`*GUI`) are listed without their methods (widget callbacks - use `show_gui()`); section-divider comments (`# ── helpers ──`) are not taken as summaries; `demo.py` (the demo notebook) is left out. `--check` exits 1 when API.md is stale. Lets a reader (or an AI assistant) find a helper and read only its source lines instead of whole modules
- `tools/pdm_file_downloader` — PDM File Downloader, moved from another project: search a SolidWorks PDM vault by item name (several, comma-separated, `*` `?` wildcards), hide markups (`_MU*`), filter by type, sort, optionally read each file's data-card Revision, and download copies of the selected files (no checkout; existing files skipped unless "Overwrite existing"). `show_gui(**kwargs)`, keys `vault` (default `'PDM Vault'`), `look_in`, `dest` (default `~\Downloads\Downloaded PDM Files`), an unknown key raises `TypeError`; a blank look-in searches from the vault's root folder. On start it checks for the PDM client (`ConisioLib.EdmVault` registered) and pywin32; if either is missing it shows only the reason and a "Show UI anyway" button. API: `pdm_missing()`, `is_markup()`, `download_files(pdm, paths, dest, overwrite, on_progress)` -> `(saved, skipped, failed)`
- `SolidWorksPDM.root_folder()` — local path of the vault's root folder
- `log_actions` — `resume=True` on `PrintLogger.start()` / `print_logging_start()`: continue the file this process last logged to in that folder, else the newest `PrintLog_YYYY-MM-DD.log` there (never e.g. `PrintLog_..._Combined.log`), else today's new file. A test that switches log folders mid-run, or restarts, keeps one file per folder instead of a new file each day. Default `False` keeps the old naming. `latest_log(folder, prefix)` returns that newest date-named file
- `[tools]` extra — pywin32 and ipywidgets, what the apps under `utils/tools` need (Windows only, so not in `[all]`, like `[win]`). Before, nothing declared pywin32 for them
- `standalone/win_service_utils.py` — Windows services in Python (pywin32): `install()` (pywin32's `pythonservice.exe` copied next to the venv's python.exe so it finds the venv, and a service PATH with the DLL folders it needs; run as an account - password from the Windows password dialog, 3 tries, each checked - or LocalSystem; start type; restart after a crash; pre-shutdown time; "Log on as a service" granted; start / stop / query allowed to a non-admin account), `uninstall()`, `start()`, `stop()`, `query()` -> `ServiceInfo`, `exists()`, `set_recovery()`, `set_preshutdown_timeout()`, `allow_user_control()`, `grant_logon_as_service()`. Install / uninstall / changes go through `standalone/elevate_utils` (one UAC prompt) when not elevated; start / stop only when refused. `ServiceBase`: a service class that runs `main()` until stopped, with `on_preshutdown()` for Windows' pre-shutdown notice (Windows waits as long as the service's pre-shutdown time allows). Used by a test agent service
- `standalone/elevate_utils.py` — on-demand elevation shared by `tools/task_scheduler` and `win_service_utils`: a module's calls listed in its `OPS` run in a short-lived elevated helper (ShellExecuteEx "runas", one UAC prompt per batch), so Jupyter / Python never runs as administrator. The helper's command line is a plain description, the module and the request as JSON (never a password); the result is its exit code. `ask_password()` (the Windows password dialog), `is_admin()`, `current_user()`, `ElevationError` (1223 = declined)
- `tools/launcher.py` — Tools launcher: finds every `utils/tools` subfolder with a `tool.toml` manifest (`name`, `entry = "package.module:function"`, optional `description`, `order`) and shows one button per tool; a click imports the tool and embeds the widget its entry function returns. Manifests are read without importing, so a tool with missing packages fails only on its own button; an unreadable manifest gives a disabled button with the reason. `discover_tools()` returns the list. Manifests added for Env Path Editor, Portable Apps Manager and Task Scheduler. Embedded in another project's `tools_launcher.py` as "lib-utils Tools"
- `widget_utils.FileBrowser` — pick a file by browsing folders in plain ipywidgets (no extra package): drive list, folder box, optional home button, folders opened on click, files matching `patterns` (e.g. `('*.py',)`) picked on click (`on_pick(path)`), skipped / hidden folders, errors in its own status line. Browses the PC that runs the kernel, also from a remote browser
- `tools/task_scheduler` — Task Scheduler: ipywidgets UI and API (Windows Task Scheduler COM API via pywin32) to add, list, enable / disable, run, stop and remove scheduled tasks, e.g. to start a monitor at boot or resume a test script after a restart. Basic settings: one exec action, triggers at startup / at log on (with delay) / daily / once, run whether logged on or not (password, or S4U) or only when logged on, highest privileges, priority (default normal, 4), time limit (default none), run on battery (default allowed), multiple instances (default ignore new); `export_xml()` / Show XML for the full definition. `add_python_script()` runs a script with the current interpreter in the script's folder. Passwords are asked for in the Windows password dialog (or passed from a script) and go to Windows only, never stored. Jupyter / Python stays non-elevated: changes that need administrator rights (at-startup triggers, S4U, highest privileges, changing tasks registered with administrator rights) run in a short-lived elevated helper after a UAC prompt, one prompt per batch, with a plain description of the change in the prompt's details and a notice just before it (`elevate='auto'`, the default; `False` for access denied instead). Actions take one task or a list; `delete_folder()` removes an empty task folder; `register_task(source=...)` marks a task as a tool's own (`TaskInfo.source`). COM errors become `TaskSchedulerError` with the reason
- `tools/portable_apps_manager` — Portable Apps Manager: ipywidgets UI to add (deploy + track), update, untrack and delete portable Windows apps from GitHub releases or fixed download URLs (URL apps detect updates from the redirect target's version, ETag or Last-Modified - chosen per app from what the server sends - and take the shown version from a file in the archive, e.g. adb's `source.properties`, the archive's top folder name, e.g. `node-v26.13.0-win-x64`, or the downloaded file name - chosen per app via `version_from`, default `auto`). A git-tracked `apps_catalog.ini` records how each app is best tracked (with a note); the Add form fills from it and "Save to catalog" writes tracked apps back, so recipes are shared by committing the file. A PATH column puts each app's `bin` folder on the User PATH (via `tools/env_path_editor`; appended, `%USERPROFILE%`-based, read live from the registry, backed up before each write); Untrack asks whether to remove the entry, Untrack & delete removes it. Prerequisite: `truststore` (added to the `[requests]` extra), so HTTPS verification uses the Windows certificate store and works behind corporate TLS inspection. Apps and installed versions live in `<root>/portable_apps.ini` (root defaults to `~\Downloads\Programs`, changeable per session). Assets are picked by a glob/regex that must match exactly one asset; updates compare the archive listing (size + CRC32, zip/7z/.7z.exe/tar) against the folder without extracting, write only new/changed files, never touch `preserve` globs, refuse to start while a file to be replaced is in use, and ask per file which stale files to remove. Each install writes an install manifest (`<root>/portable_apps.manifests/<name>.json`: every file written, with size + CRC32), so the next update leaves files the tool never wrote (app settings, user data) alone without a `preserve` glob, and keeps shipped files that were edited since the install unless the user picks them for overwrite. The ini is written one app at a time (re-read, that app's section replaced or removed, written back), and every action re-reads it first when it changed on disk, so hand edits and a second copy of the tool are not overwritten
- `tools/env_path_editor` — Env Path Editor: ipywidgets UI and API to view, check and edit the Windows User and System PATH (raw registry values, `%VAR%` entries kept unexpanded, value type kept). Flags empty entries, unresolved variables, relative paths, missing folders, files, duplicates (compared as expanded absolute paths, case- and trailing-backslash-insensitive) and User entries already in System. No sorting: Move up / down, Add / Add at top / Replace selected, Remove selected, Select flagged, Remove duplicates & empty. Save refuses if either PATH changed outside the tool since load, optionally backs up both raw values to `%TEMP%\env_path_editor_backups` (`restore_backup()` writes one back exactly), then broadcasts `WM_SETTINGCHANGE`. System is read-only unless running as administrator. API for other tools: `update_user_path(add, remove, prepend, backup_first)`, `add_user_path`, `remove_user_path`, `in_path`
- `pyproject.toml` — modern packaging metadata with `extras_require` groups (`requests`, `git`, `crypto`, `pdf`, `slack`, `selenium`, `math`, `win`, `all`)
- `README.md` — package layout, install instructions, usage examples

### Changed
- One-line `#` comments above 148 public functions / classes whose name doesn't tell their behaviour: return values on failure (`None` vs `[]` vs a status string), side effects (`write_file()` appends unless `overwrite=True`, `UtilityFunctions()` replaces `sys.exit` in Jupyter, `SQLite.query()` doesn't commit), formats and units (timestamp styles, relative error as a fraction), and gotchas (`module_exists()` takes the pip distribution name, `send_webhook()` skips TLS verification). Self-explanatory helpers (`set_bit`, `get_hostname`, ...) and widget callbacks are left without one. API.md picks them up as summaries
- `tools/task_scheduler` — the elevated helper moved to the shared `standalone/elevate_utils`; `_elevated.py` now only lists the calls it may make (`OPS`, `run_op`). Same API and behaviour; the password dialog and `is_admin()` / `current_user()` come from `elevate_utils`
- `requires-python` raised to `>=3.11` (`tools/launcher.py` reads `tool.toml` with the standard-library `tomllib`)
- `requirements.txt` — rewritten as a flat `>=` mirror of the `pyproject.toml` dependencies (same floors), replacing the stale pip-freeze pins (`cryptography==45.0.7` contradicted pyproject's `>=48.0.1`); added previously missing sections (`ipython` core, `[sql]`, `[cv]`, `[clipboard]`, `[pillow]`, `[widgets]`); dropped transitive `pywin32-ctypes`. `pip-audit` re-run 2026-07-18 on the full resolved set (73 packages incl. transitives): no known vulnerabilities

### Removed
- `setup.py` — the shim (all metadata already lived in `pyproject.toml`) is no longer needed; PEP 660 editable installs work from `pyproject.toml` alone with `setuptools>=68`
